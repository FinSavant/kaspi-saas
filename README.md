# Kaspi SaaS

Сервис для продавцов Kaspi.kz: склейка накладных, демпинг-бот (репрайсер) и аналитика продаж. Веб-кабинет и Telegram-бот.

## Структура

```
packages/
  db/            Prisma-схема (PostgreSQL) и клиент
  core/          чистая логика: расчёт цены, склейка PDF, метрики, шифрование токенов
  kaspi-client/  Kaspi Merchant API, кабинет продавца, витрина, XML-прайс-лист
  storage/       хранилище PDF: локальная папка или Google Cloud Storage
apps/
  api/           Fastify: прайс-лист для Kaspi, товары, накладные, аналитика
  worker/        BullMQ: репрайсер, синхронизация товаров и заказов, склейка накладных
  bot/           Telegraf: /print, /repricer_on, /repricer_off
  web/           Next.js: товары и демпинг-бот, накладные, аналитика
deploy/          Dockerfile, манифесты Kubernetes и Cloud Run
scripts/         add-shop, mc:login, check:kaspi
```

## Запуск локально

Нужны Node.js 22+ и Docker Desktop (для PostgreSQL и Redis).

```bash
npm install
cp .env.example .env        # заполнить ключи
docker compose up -d
npm run db:migrate
npm run add-shop -- <merchantId> "<название магазина>"
npm run mc:login            # вход в кабинет Kaspi для синхронизации товаров
npm run dev:api             # и в отдельных окнах: dev:worker, dev:web, dev:bot
```

Кабинет: `http://localhost:3000/shops/<shopId>/products` и `/shops/<shopId>/waybills`.

## Накладные

Склейка запускается только по кнопке «Склеить накладные» (или `/print` в Telegram). В неё попадают только заказы вкладки «Передача» кабинета Kaspi: в API это `KASPI_DELIVERY` с `assembled=true`, ссылкой на накладную и пустой `courierTransmissionDate` (`isAwaitingHandover` в `packages/kaspi-client/src/client.ts`). Каждый заказ склеивается один раз; накладные, которые Kaspi ещё не сформировал, пропускаются и попадают в следующую склейку.

Исходные накладные Kaspi — страницы 100×150 мм, поэтому формат «Термопринтер» оставляет их как есть. Форматы A4 раскладывают по 4 или 8 на лист. Любую прежнюю склейку можно пересобрать в другом формате без новых отметок о печати.

Накладные можно сортировать (по товару, по товару и городу) и фильтровать: только новые, без экспресс-заказов, за период, по городам, товарам и номерам заказов. Список заказов «Передачи» для фильтров загружается кнопкой.

## Аналитика

Раздел устроен как у WaybillPrint: периоды «Сегодня / Вчера / 7 / 30 / 90 дней / Год» и свой диапазон, плитки (выручка, заказы, средний чек, отмены, среднее время до передачи курьеру) и вкладки «Обзор», «Выручка», «Товары», «География», «Доставка и оплата», «Прибыль», «В пути», «Отмены».

- **Продажи** — только выданные заказы (`COMPLETED`).
- **«В пути» (нереализованная прибыль)** — все заказы в работе за любую дату: сколько денег ожидается и какая прибыль будет после удержаний.
- **Прибыль** = выручка − себестоимость − комиссия Kaspi по категории − НДС на комиссию (16%) − Kaspi Pay (0,95%) − доставка. Доставка — фактическая сумма из Kaspi API по каждому заказу. Ставки комиссий — `scripts/kaspi-commissions-2026.ts` (официальные тарифы Kaspi 2026, `npm run seed:commissions`).

Заказы загружаются за год (`npm run sync:orders -- --full`), дальше воркер обновляет их раз в 30 минут, включая старые заказы, которые ещё в пути.

## Синхронизация товаров

Официальный API Kaspi не отдаёт список товаров продавца, поэтому товары берутся из кабинета продавца — тем же запросом, которым страница «Управление товарами» загружает вкладку «В продаже» (`packages/kaspi-client/src/cabinet.ts`). Так же работает WaybillPrint.

1. В кабинете Kaspi («Управление пользователями») создаётся отдельный пользователь только с правом «Загрузка товаров»; его логин и пароль записываются в `.env` (`KASPI_MC_LOGIN`, `KASPI_MC_PASSWORD`).
2. `npm run mc:login` входит в кабинет, при необходимости спрашивает код из почты и сохраняет сессию в базе зашифрованной. Устройство запоминается.
3. Кнопка «Синхронизировать товары с Kaspi» загружает товары в продаже: артикул, номер карточки, название, бренд, категорию, цену в городе магазина и сумму остатков по складам. Товары, снятые с продажи, скрываются. Цена товара с включённым ботом не перезаписывается.
4. Затем по каждой карточке считается число продавцов (запрос к витрине, см. ниже), чтобы было видно открытые карточки.

Если сессия истекла, воркер входит заново по паролю. Если Kaspi при этом просит код из почты, синхронизация останавливается с просьбой выполнить `npm run mc:login`.

## Откуда берутся цены конкурентов

`KaspiStorefrontPriceSource` (`packages/kaspi-client/src/storefront.ts`) запрашивает список продавцов с публичной карточки товара — тем же запросом, которым карточка загружает блок «Продавцы». Браузер для этого не нужен. Это не официальный API: Kaspi может изменить его, ограничить частоту запросов или заблокировать адрес, а автоматический сбор может нарушать условия использования сайта.

## Как цена попадает в Kaspi

Репрайсер записывает новую цену в таблицу `Product`. `api` отдаёт прайс-лист по адресу `/feeds/:shopId/price.xml`; эту ссылку продавец указывает в кабинете Kaspi, и Kaspi сам забирает файл по своему расписанию. Скорость обновления цены поэтому зависит от Kaspi, а не от бота.

## Что не сделано

- **Прокси.** Ротации прокси нет. Запросы к витрине идут с одного адреса, по одному, с паузой `STOREFRONT_MIN_INTERVAL_MS`.
- **Авторизация пользователей.** Регистрации и входа нет. `api` защищён одним общим секретом `API_INTERNAL_KEY` и не проверяет, чей магазин запрашивается — выставлять его в интернет в таком виде нельзя. Логин кабинета Kaspi пока один на всю установку (`.env`).
- **Подключение магазина.** Нет формы: магазин добавляется командой `npm run add-shop`.
- **Позиции заказов.** `syncOrders` загружает заказы без позиций (`OrderItem`) и не запускается по расписанию, поэтому аналитика по реальным данным пока пуста; дашборд показывает демонстрационные цифры.
- **Агрегаты `DailyProductStat`** для ABC/XYZ никто не заполняет.
- **Оплата и подписки.** Таблица `Subscription` есть, логики нет.

## Что проверено, а что нет

- **Проверено на живом магазине:** заказы через Kaspi API, определение вкладок «Упаковка», «Передача», «Переданы в доставку», склейка реальных накладных в форматах A4 и «Термопринтер», кнопки склейки и пересборки в кабинете.
- **Не проверено:** вход в кабинет и синхронизация товаров с сервера (запросы выяснены по коду страниц кабинета и проверены только из браузера), подсчёт продавцов и работа репрайсера на реальных карточках, приём XML-прайс-листа Kaspi, Telegram-бот, сборка Docker-образов и Skaffold.

## Развёртывание

`skaffold run` разворачивает все четыре сервиса в Kubernetes (GKE); переменные окружения берутся из секрета `kaspi-saas-env`. Профиль `skaffold run -p cloudrun` разворачивает в Cloud Run только `api` и `web`: `worker` и `bot` не слушают HTTP-порт и как сервисы Cloud Run не работают.

Сервисы `api`, `worker` и `bot` в контейнере запускаются из исходников TypeScript через `tsx`, без отдельной сборки.
